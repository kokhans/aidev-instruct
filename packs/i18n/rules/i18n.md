# Internationalization

## URLs and Language Choice

- Each language has its own URL with one pattern across the site, such as a path prefix: `/de/pricing`.
- The locale comes from the URL, never from a cookie or header alone, so every version is linkable and crawlable.
- Never redirect automatically by `Accept-Language` or IP. Suggest another language with a dismissible banner and offer a language switcher.
- The switcher links to the same page in each language, labels each language in its own name, and sets `hreflang` and `lang` on each link.
- `<html lang>` and `dir` match the page language. Inline phrases in another language carry their own `lang`.

## Messages

- No user-visible string is hard-coded in components. Strings live in per-locale message catalogs with stable keys.
- Messages use ICU MessageFormat or the library's equivalent for plurals, select and variables. Never build sentences by concatenating fragments.
- Plurals use the locale's plural categories (`Intl.PluralRules`), never `count === 1`.
- A missing translation falls back to the default locale and is reported in development and CI.
- Translated text is often much longer than English. Layouts never depend on string length.

## Formatting

- Dates, times, numbers, currencies, units, lists and relative times use `Intl` APIs with the page locale, never manual formatting.
- Timestamps are stored in UTC. Formatting passes an explicit `timeZone`, so server and client render the same text and hydration does not mismatch.
- Sorting user-visible text uses `Intl.Collator` or `localeCompare` with the locale.
- Currency comes from the data, never from the locale.

## Layout

- CSS uses logical properties (`margin-inline-start`, `padding-block`, `inset-inline-end`) so right-to-left languages work without overrides.
- Directional icons (arrows, chevrons) mirror in right-to-left. Logos, media controls and numbers do not.
- Web fonts cover every script the site serves, with subsets per script.

## Content

- Each language version has its own translated title, description, share image text and slug when the CMS supports it.
- Legal pages exist in every language the site sells or collects data in.
